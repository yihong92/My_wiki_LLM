MCP 是什麼

MCP 是一個開放標準，規定 AI 應用程式要用什麼共同格式，去連接外部的資料與工具。

一句話定義

Model Context Protocol 是 Anthropic 在 2024 年 11 月開源的協定，用來把 AI 助理接到資料實際存放的地方，例如文件庫、商業軟體和開發環境。S1 官方文件把它描述為：替大型語言模型（LLM）提供上下文的標準化方式。S2

名字拆開來看

字意思
Model大型語言模型，例如 Claude、GPT 這類會讀文字、產生文字的 AI。
Context模型回答時能參考的資訊：檔案內容、資料庫紀錄、工具清單、執行結果等。
Protocol雙方事先約好的溝通規則，像 HTTP 規定瀏覽器和網站怎麼說話。

USB-C 比喻

官方與許多教學文章都用 USB-C 來比喻 MCP：以前每種裝置都有自己的接頭，USB-C 讓一種接頭就能接各種周邊；MCP 則讓 AI 應用用同一種「接口」去接各種資料來源與工具。S6

比喻的界線：USB-C 不會讓裝置變聰明，它只讓「連接」不再是問題。MCP 同樣不會讓模型更聰明，它只負責交換上下文，不規定應用程式要怎麼使用 LLM。S2

MCP 不是什麼

  • 不是一個模型，也不是某家公司的專屬功能；任何 AI 應用都能實作。S5
  • 不是 Function Calling 的替代品，而是建立在它之上的連接標準（見 比較頁）。
  • 不會自動保證安全；安全程度取決於實作與部署方式（見 安全頁）。

要解決的問題：M×N

模型再強，如果拿不到資料，就像被關在房間裡的專家。

資料孤島

Anthropic 在發布文中指出：模型的推理能力進步很快，但它們被隔絕在資訊孤島和舊系統之外；每接一個新資料來源，就要寫一套專屬的整合程式，系統很難擴大。S1

M×N 變成 M+N

假設有 M 個 AI 應用（聊天機器人、程式編輯器、客服系統……）和 N 個工具（GitHub、Slack、資料庫……）。沒有共同標準時，每一對都要客製連線，最多需要 M×N 套整合。有了 MCP，每個工具只要寫一次 MCP Server，每個應用只要實作一次 MCP Client，總數變成 M+N。S6

情境3 個 AI 應用 × 4 個工具10 個應用 × 20 個工具
各自客製（M×N）12 套200 套
透過 MCP（M+N）7 個實作30 個實作

數字是示意用的計算，用來說明成長速度的差異，不是調查數據。

架構：Host、Client、Server

MCP 採用主從（client-server）架構，裡面有三個角色。

角色是什麼例子
MCP Host使用者實際操作的 AI 應用程式，負責協調一個或多個 Client。Claude Desktop、Claude Code、VS Code
MCP ClientHost 內部的元件，和「一個」Server 維持專屬連線，替 Host 取得上下文。VS Code 連上 Sentry 時建立的連線物件
MCP Server提供上下文的程式，可以跑在本機或遠端。檔案系統 Server（本機）、Sentry Server（遠端）

來源：S2

一對一的連線

Host 每連一個 Server，就建立一個新的 Client。官方範例：VS Code 連上 Sentry 的 MCP Server 時會建立一個 Client 物件；再連本機檔案系統 Server 時，又建立另一個。S2

VS Code（Host）
 ├─ Client 1 ──專屬連線── 檔案系統 Server（本機）
 └─ Client 2 ──專屬連線── Sentry Server（遠端）

兩層結構

  • 資料層（內層）：用 JSON-RPC 2.0 定義訊息格式，包含生命週期管理與各種原語（tools、resources、prompts、通知）。S2
  • 傳輸層（外層）：定義訊息怎麼送過去，包括建立連線、訊息分框與授權。見 傳輸層。S2
初學者提醒：「Server」指提供上下文的程式本身，不一定是遠端機房裡的伺服器。它可以就是你電腦上跑的一個小程式。S2

原語：Server 和 Client 能互相提供什麼

「原語」（primitive）是 MCP 最重要的概念：它定義了雙方能交換哪些東西。

Server 提供的三種原語

原語用途例子主要方法
Tools 工具可執行的函式，讓 AI 去「做事」查資料庫、呼叫 API、寫檔案tools/list、tools/call
Resources 資源提供上下文的資料，讓 AI 去「讀」檔案內容、資料表結構、API 回應resources/list、resources/read
Prompts 提示範本可重複使用的互動範本系統提示、few-shot 範例prompts/list、prompts/get

每種原語都有 */list 方法讓 Client 先「探索」有哪些可用，所以清單可以動態變化。S2

綜合例子：資料庫 Server

一個資料庫 MCP Server 可以同時提供：查詢資料的工具、內含資料表結構的資源，以及示範如何使用這些工具的提示範本。S2

Client 提供的原語（反方向）

  • Sampling 取樣：Server 請 Host 的模型幫忙產生文字，Server 自己就不必綁定某家模型。S2
  • Elicitation 詢問：Server 請使用者補充資訊或確認某個動作。S2
  • Logging 紀錄：Server 把日誌訊息傳給 Client，方便除錯與監控。S2
為什麼重要：Function calling API 只提供工具，RAG 只提供資料，提示庫只提供範本；MCP 把三者放在同一個介面後面，還能在執行時查詢有哪些可用。S6

一次互動的訊息流程

用官方文件裡的「天氣工具」例子，看 Client 和 Server 實際交換了什麼。

步驟 1 適用 ≤ 2025-11-25；2026-07-28 已改，見版本頁

1. 建立連線（舊版：initialize 握手）

在 2025-06-18 等版本中，Client 先送 initialize，雙方交換協定版本與各自支援的能力，之後 Client 送 notifications/initialized 表示準備好了。S2 在 2026-07-28 版本中，這個握手已被移除，改成每個請求自己帶版本與能力資訊。S3

2. 探索工具：tools/list

Client 問 Server 有哪些工具。Server 回傳一份清單，每個工具有 name、title、description，以及用 JSON Schema 描述參數的 inputSchema。S2

{ "jsonrpc": "2.0", "id": 2, "method": "tools/list" }

3. 呼叫工具：tools/call

模型決定要用某個工具時，Host 攔下這個呼叫，轉給對應的 Server 執行，再把結果放回對話給模型參考。S2

{
  "jsonrpc": "2.0", "id": 3, "method": "tools/call",
  "params": { "name": "weather_current",
              "arguments": { "location": "San Francisco" } }
}

回應的 content 是一個陣列，可以放文字、圖片等不同型態的內容。S2

4. 主動通知：notifications/tools/list_changed

工具清單改變時，Server 可以主動通知 Client。通知沒有 id，也不需要回覆；Client 收到後通常會重新呼叫 tools/list。S2

傳輸層：stdio 與 Streamable HTTP

同樣的 JSON-RPC 訊息，可以走兩種不同的「管線」送過去。

stdioStreamable HTTP
位置同一台電腦上的兩個程式透過網路連到遠端
方式用標準輸入／輸出串流直接溝通用 HTTP POST 送訊息，可選擇用 Server-Sent Events 串流
常見稱呼本機（local）Server遠端（remote）Server
服務對象通常只服務一個 Client通常同時服務多個 Client
例子Claude Desktop 啟動的檔案系統 ServerSentry 官方的 MCP Server

來源：S2

授權

遠端傳輸支援 bearer token、API key 等標準 HTTP 驗證方式，官方建議用 OAuth 取得權杖。S2 2026-07-28 版本也加入了驗證授權回應中 issuer 參數的要求，用來防範 OAuth 混淆攻擊。S8

剛發布時 MCP 只能連本機 Server，遠端 Server 與企業級驗證當時仍在開發中，之後才推出。S5 S3

規格版本與無狀態化

MCP 規格用「發布日期」當版本名稱，所以讀資料時一定要看它講的是哪一版。

版本重點
2025-06-18官方架構教學採用的版本：連線以 initialize 握手開始。S2
2025-11-252025 年 11 月的版本。S3
2026-07-28目前最新版。核心改為無狀態：移除 initialize/initialized 握手與 Mcp-Session-Id 標頭，每個請求自帶版本、Client 身分與能力資訊。S3

「無狀態」對初學者的意義

以前的 MCP 像打電話：要先接通、互相確認聽得到，之後的對話都在同一通電話裡。2026-07-28 版本比較像寄信：每封信自己寫清楚寄件人和格式，任何一台伺服器收到都能處理。官方說，請求因此可以交給一般的輪替式負載平衡器分配，不需要共享的連線狀態儲存。S3

The Register 的報導提到，這版也加入了功能生命週期與棄用政策，讓企業能預期規格變動的時程。S8

讀資料時的陷阱：網路上大多數 2025 年的教學都還在講 initialize 握手。那些內容在舊版是對的，但不代表最新規格。本 Wiki 在受影響的頁面都標了版本。

MCP 與 Function Calling

兩者是上下層的關係，不是二選一。

Function Calling（工具使用）MCP
層級模型層的能力：模型選擇工具並填好參數連接層的標準：規定 Host 怎麼找到並呼叫外部工具
範圍一個模型呼叫一個應用裡定義好的工具許多應用共用許多工具與資料來源
格式各家模型廠商的格式不同一套共同協定
適合單一應用、少數工具、兩端都由你控制很多 Client 需要同一組工具

來源：S6

關係怎麼記

MCP 底層仍然使用 function calling：MCP 的 tools 原語會對應到模型原生的工具呼叫介面。可以想成 function calling 決定「模型怎麼按下按鈕」，MCP 決定「按鈕的插頭長什麼樣」。S6

什麼時候不需要 MCP

如果只有一個應用、一個模型、兩三個內部工具，直接用 function calling 通常更簡單。之後若需要讓別的應用重用，把原本的函式包進 MCP Server 即可，函式本體不必重寫。S6

安全風險與防護

MCP 讓模型能「做事」，所以被騙的代價也從說錯話變成做錯事。

三種常見風險

風險怎麼發生
間接提示注入工具讀回來的內容（網頁、工單、郵件、檔案）夾帶指令，模型把它當成要照做的命令。S7
工具投毒惡意指令藏在 Server 提供的工具描述、參數說明或錯誤訊息等中繼資料裡，而模型本來就被設計成相信這些描述。S7
Rug pull（中途變臉）Server 一開始正常，取得信任後更新成惡意版本。S7

防護習慣

  • 把工具的輸入輸出都當成不可信資料，不要讓模型自動照著讀到的內容行動。S7
  • 寫入、寄送、付款、刪除等動作要人工確認，工具有變動時重新確認。S7
  • 固定 Server 版本並比對工具描述，更新時檢查差異；第三方 Server 要先審查再啟用。S7
重點：授權機制（OAuth）只保護「誰能連」，擋不住工具投毒或間接注入；MCP 部署是否安全，主要看 Host、Server 與企業管控怎麼設定。S7

WIKI / 比較與實務 / 發展歷程

發展歷程與治理

時間事件
2024-11-25Anthropic 開源 MCP，同時釋出規格與 SDK、Claude Desktop 的本機 Server 支援，以及開源的 Server 範例庫（Google Drive、Slack、GitHub、Git、Postgres、Puppeteer）。創造者是 David Soria Parra 與 Justin Spahr-Summers。S1
2024-11首批 SDK 為 TypeScript 與 Python；Block、Apollo 已整合，Zed、Replit、Codeium、Sourcegraph 等開發工具公司投入支援。S1 S5
2025-12-09Anthropic 把 MCP 捐給 Linux 基金會旗下新成立的 Agentic AI Foundation（AAIF），與 Block 的 goose、OpenAI 的 AGENTS.md 並列創始專案。AAIF 由 Anthropic、Block、OpenAI 共同創立，Google、Microsoft、AWS、Cloudflare、Bloomberg 支持。S4
2026-07-28發布無狀態核心的新規格。官方部落格表示，各 Tier 1 SDK 每月下載量接近 5 億，TypeScript 與 Python SDK 累計都超過 10 億次。S3

為什麼捐給基金會很重要

Anthropic 表示捐贈是為了讓 MCP 保持開源、社群驅動且不偏向任何廠商。S4 對企業來說，協定不再由單一公司掌控，長期採用的風險較低。

查證紀錄：有一篇第三方網站文章把捐贈日期寫成 2026 年 5 月，與 Anthropic 及 MCP 官方部落格的 2025-12-09 不符，本 Wiki 採用官方日期。詳見 建置日誌。
